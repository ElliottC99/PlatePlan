PlatePlan is a zero-bundler ES-module PWA backed by Firebase Firestore (households/elliott-chloe). Rapid feature velocity left three structural drag points: broken legacy UI bindings (data-pp-*), parallel module owners (State, Data Quality, Action Sheets), and full-DOM re-renders / unversioned sub-module imports. At the same time, two tests (test_accessibility_dom.js / npm run lint and test_recipe_wizard.js) fail out-of-the-box, weakening the CI/local safety net.

Topic Axes

1. Simplification

Consolidate parallel modules, delete expired attic files, and remove dead UI controls.

2. Reliability & Quality

Fix broken lint/wizard tests, unify Firestore writers, and restore dead data-pp-* controls.

3. Product & UX Development

Persistent planner layout, smoother mobile shopping/today workflows, and household polish.

4. Runtime Optimisation

Targeted DOM patching, sub-module cache-busting, and splitting 1,000-line service monoliths.

Ranked Ideas

I1. Repair or Rewire the 30 Dead data-pp-* Controls & Retire Inline onclick

Reliability & QualityConfidence: HighComplexity: M

What it is: Audit all 30 remaining data-pp-click / data-pp-change / data-pp-input attributes in index.html and src/, migrate live ones (vault filter/sort, pantry search, add-ingredient, Tesco import) to ActionBridge.js data-action / delegated change/input handlers, and delete truly dead markup.

Basis (direct): AGENTS.md explicitly documents that ActionBridge.js no longer handles data-pp-*, leaving 30 controls across index.html and src/ silently broken, alongside 127 inline onclick= attributes.
Tradeoff: Requires touching index.html and multiple view templates; best done view-by-view (Vault, Pantry, Planner) so regressions stay isolated.

I2. Consolidate the 6 Parallel Modules & Purge the 80 Expired attic/ Files

SimplificationConfidence: HighComplexity: M

What it is: Collapse the 3 duplicate App State modules (store/state.js, state/AppState.js, models/StateModel.js) into store/coreState.js, merge the 2 parallel Data Quality scanners into DataQualityScanner.js, merge the duplicate pantry/ActionSheetUI.js into navigation/ActionSheetUI.js, and delete the 80 attic/ files whose delete-after dates (2026-11-11–2026-11-13) have passed.

Basis (direct): LEDGER.md reports 6 parallel modules across those exact 3 jobs, 95 unused exports, and 80 expired files in attic/.
Tradeoff: Touching coreState.js / state callers requires careful grep verification across scripts and tests.

I3. Restore npm run lint & Add a Single-Command CI Test Runner

Reliability & QualityConfidence: HighComplexity: S

What it is: Point scripts/test_accessibility_dom.js at index.html instead of the deleted PlatePlan.html, fix the stale assertion in scripts/test_recipe_wizard.js, and add an npm test script + GitHub Actions step that runs all core scripts/test_*.js suites on every PR.

Basis (direct): AGENTS.md notes npm run lint and test_recipe_wizard.js fail before any change is made, and .github/workflows/pages.yml only syntax-checks and builds without running behavioral tests.
Tradeoff: A few older test scripts assume local/mocked state or take 5–10s; CI should run a curated fast suite (~15–20s).

I4. Targeted DOM Patching & Cache-Busted Module Graph

Runtime OptimisationConfidence: HighComplexity: M

What it is: Replace full-view innerHTML re-renders (e.g. toggling a shopping list tick in ShoppingView.js re-rendering the entire Planner Wizard) with targeted row DOM updates, and stamp ?v=__BUILD_ID__ (or an import map) across src/ imports during npm run build so phones never run mixed old/new ES modules after a deploy.

Basis (direct): ShoppingView.js:41 calls window.renderPlannerWizard() on every checkbox tick, and index.html:1321 only stamps ?v=__BUILD_ID__ on src/main.js, leaving all static/dynamic sub-imports unversioned in browser caches.
Tradeoff: Build-time import rewriting needs a clean test in scripts/test_pwa_build.js so unbuilt npm run dev continues working seamlessly.

I5. Persist Planner Layout Grid & Add Multi-Week / Plan-Template Reuse

Product & UX DevelopmentConfidence: MedComplexity: M

What it is: Save skeletonGrid in cacheSlice.js (surviving refreshes even before generating a plan) and let users save named Layout Grid templates (e.g. "Standard Work Week" with lunches pinned and Friday dinner skipped) to reuse across weeks.

Basis (direct): cacheSlice.js does not persist skeletonGrid, and PlannerSkeletonGridUI.js only lives in memory until a plan is generated/saved.
Tradeoff: Adds a small Firestore/localStorage schema field for saved grid templates; keep optional until basic persistence lands.

I6. Decompose RecipeEnhancementService.js (1,205 LOC) & Extract restoredGnocchi.js Seed Data

SimplificationConfidence: HighComplexity: M

What it is: Split RecipeEnhancementService.js (1,205 lines) along real boundaries (macro-gap rules, swap-candidate matching, nutrition quantization), and move restoredGnocchi.js (844 lines of static fallback recipe JSON) out of the main runtime bundle into lazy JSON or remove it if Firestore already holds the recipe.

Basis (direct): find src -name '*.js' -exec wc -l shows RecipeEnhancementService.js (1,205) and restoredGnocchi.js (844) are two of the three largest files in the 41.5k-LOC codebase.
Tradeoff: Needs grep verification to confirm whether restoredGnocchi.js is still required as a seed/test fixture.

I7. Enforce Single-Writer Repositories for recipes and ingredients

Reliability & QualityConfidence: HighComplexity: M

What it is: Route all Firestore writes to recipes and ingredients exclusively through RecipeFirestoreRepository.js and PantryTaxonomyService.js (matching how products is already single-writer via ProductRepository.js) so schema normalization and cache updates never drift across callers.

Basis (direct): AGENTS.md notes that only products has achieved single-writer status while recipes and ingredients are still written from multiple modules.
Tradeoff: Requires auditing all .collection('recipes') and .collection('ingredients') write sites across src/.
